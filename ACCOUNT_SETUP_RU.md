# MuQwiz accounts & sync — установка

В этой версии добавлены UI регистрации/входа по логину и паролю, email для восстановления, локальное сохранение и синхронизация JSON-снимка APP с Supabase. Локальные данные сохраняются при отсутствии сети; повторная отправка выполняется при событии online и после следующих изменений.

## Обязательная настройка Supabase
1. Открой SQL Editor своего Supabase-проекта и выполни `supabase/migrations/202610200001_accounts.sql`.
2. В Authentication → URL Configuration укажи реальные Site URL и Redirect URLs, включая `/reset-password.html` на своём домене и localhost для разработки.
3. В Authentication → Providers → Email настрой подтверждение email. При включённом подтверждении пользователь должен подтвердить email перед входом.
4. Разверни функцию `username-auth` через Supabase CLI: `supabase functions deploy username-auth`.
5. Проверь secrets функции: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. Service role key НИКОГДА не добавляй в клиентские файлы.
6. Проверь Email SMTP/письма подтверждения и сброса пароля. Ограничь частоту вызовов Edge Function на уровне инфраструктуры/защиты от злоупотреблений.

## Важные ограничения этой первой реализации
- Синхронизируется JSON-снимок профиля, викторин, результатов, заметок, избранного и настроек. Само содержимое MP3 не копируется в `user_data`; аудио остаётся в текущем Storage/по ссылкам.
- Офлайн-изменения сохраняются в localStorage и отправляются при следующем изменении/возврате сети. Это не полноценная очередь операций с разрешением конкурентных правок: при нескольких устройствах, одновременно изменяющих одни данные, возможна стратегия «последняя запись победила». Перед массовым запуском нужна проверка конфликтов.
- Если в облаке и локально есть данные, при входе предлагается объединение или загрузка облачной копии; перед заменой локальная копия сохраняется в `muqwiz_pre_cloud_backup`.
- Старая локальная база не удаляется автоматически.
- Для существующего проекта проверь, что URL и publishable key в `account.js` соответствуют проекту. Ключ в браузере является публичным ключом и безопасен только при корректных RLS-политиках.
- Миграция SQL и Edge Function должны быть применены к тому же Supabase-проекту, что указан в клиенте. В этой среде невозможно проверить реальные секреты, отправку email и сетевые политики проекта.
